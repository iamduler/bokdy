# I18n

Version: 1.0

Status: Active

Vietnam-first. UI chrome is next-intl. Display names in Postgres use `name_en` + `name_vi`. Locale 3+ uses `*_translations` without dropping those columns.

---

# Layers

| Layer | What | Where |
| --- | --- | --- |
| L1 | Buttons, errors, status labels (`canceled`) | next-intl `en` + `vi` |
| L2 | Platform catalogs (country, currency, sport, …) | `name_en` + `name_vi` both required |
| L2 exception | `reference.locales` | `name` (English label) + `native_name` (endonym: Tiếng Việt, English) + `emoji` (flag). Not `name_en`/`name_vi`. |
| L3 | Tenant-authored (Organization, Branch, Court, service, …) | at least one of `name_en` / `name_vi` |

Do not store L1 copy in the database.

Do not add `name_th` (or any third language column). Do not store locale maps in jsonb.

---

# API locale

Every HTTP request is localized from `Accept-Language`.

- Missing, empty, or unparseable → `vi`
- First tag wins (`vi-VN` → `vi`, `en-US` → `en`)
- No `?locale=` query. No `X-Locale` header.
- BFF `/api/go/*` forwards `Accept-Language` from the browser.
- User/tenant `locale_id` preference does **not** override the header. Use preference only for mail and jobs with no request.

Read/list/detail (marketplace, org picker): return resolved `name` (and `description` when present).

Owner edit payloads: return and accept `name_en` + `name_vi`.

`message` is not translated by Go. FE maps `code` (and `details[].code`) through next-intl `errors.*`. Codes are UPPERCASE; catalog: `packages/config/error-codes.json`.

---

# Resolve

```text
ParseLocale(Accept-Language) → first supported tag or "vi"

DisplayName(locale, name_en, name_vi, extra?):
  if locale not in {en, vi}:
    if extra[locale].name != "": return it
  if locale == vi && name_vi != "": return name_vi
  if locale == en && name_en != "": return name_en
  return firstNonEmpty(name_vi, name_en)
```

One helper: `bokdy/internal/platform/i18n`. Handlers must not parse `Accept-Language` themselves.

# Locale 3+

Create `{schema}.{entity}_translations`:

- `id` uuid PK
- `{entity}_id` + `locale_id` unique
- overlay display fields only (`name`, `description`)

See `reference.country_translations` as the template. Do not pre-create empty translation tables for every aggregate.

---

# Exclusions

Keep a single `name` (or person-name columns) for:

- `first_name`, `last_name`, `full_name`, `display_name`
- `event_name`, queue topic, `device_name`
- `identity.personal_access_tokens.name`
- `infrastructure.job_definitions.name`, `infrastructure.feature_flags.name`

`reference.locales` uses `name` + `native_name` + `emoji` (English label + endonym + flag). Do not run `DisplayName` on locale rows. Countries and currencies stay `name_en` + `name_vi`.
